# Dubai Days — самостоятельный сайт на GitHub Pages

Это **только безопасная оболочка путеводителя**. Личный маршрут, бронирования,
точные даты, бюджет и другие данные поездки не включены в репозиторий.

## Запуск на своём GitHub

1. Создайте **новый публичный** репозиторий, например `dubai-days-app`, в
   своём аккаунте. **Не открывайте** старый `Lucky2356/dubai`: в его истории
   остались личные данные.
2. Загрузите содержимое этого пакета в корень нового репозитория, сохранив
   структуру папок `public/` и `.github/workflows/`.
   Для загрузки из локального Git-клона используйте обычный `git add`, `git commit`, `git push`.
3. В GitHub откройте **Settings → Pages → Build and deployment → Source** и
   выберите **GitHub Actions**.
4. На вкладке **Actions** найдите `Publish Dubai Days` и выберите **Run workflow**
   (либо просто сделайте следующий push в `main`).
5. Дождитесь успешного запуска: ссылка появится в разделе **Settings → Pages**.
   Для репозитория `dubai-days-app` ссылка обычно имеет вид
   `https://Lucky2356.github.io/dubai-days-app/`.
6. Откройте сайт по HTTPS, импортируйте **отдельный личный JSON-файл** и
   установите пароль длиной не менее 12 символов.

## Как управлять сайтом самостоятельно

Редактируйте код в `public/`, затем отправляйте изменения в ветку `main`.
GitHub Actions автоматически публикует новую версию. Никакое обращение к
ChatGPT для этого не требуется.

- Адрес сайта: https://lucky2356.github.io/dubai-days-app/
- Исходники и история обновлений: https://github.com/Lucky2356/dubai-days-app
- Отслеживание публикаций: вкладка **Actions → Publish Dubai Days**.
- Публичная оболочка обновляется с GitHub автоматически, а личный маршрут,
  расходы и билеты остаются в зашифрованном хранилище браузера.

## Личные данные: резервная копия, перенос и обновление

1. После входа откройте **⚙ Настройки → Скачать защищённую копию**. Сохраните
   полученный `dubai-days-protected-*.json` в надёжном месте. Пароль храните отдельно.
   В настройках также показывается дата последней подготовки файла. Убедитесь,
   что скачивание действительно завершилось и файл находится в загрузках.
2. На другом телефоне или компьютере откройте тот же адрес сайта и выберите
   **Восстановить защищённую копию**. Укажите скачанный файл и его пароль.
   Восстановятся сам маршрут, отметки, расходы, билеты и настройка карты —
   **без автоматической синхронизации**.
3. Если вы получили новую версию личного JSON, откройте **⚙ Настройки →
   Обновить маршрут из JSON**. Введите текущий пароль: существующие отметки,
   расходы и вложения сохранятся. Перестановка **тех же этапов внутри одного дня**
   переносит отметки за соответствующими этапами. Изменение состава этапов,
   дат или неоднозначный повторяющийся маршрут блокируется, чтобы не привязать
   старый прогресс к другим местам. До изменений скачайте защищённую копию.
4. Откройте **⚙ Настройки → Защитить данные от автоматической очистки**,
   если кнопка доступна. Браузер может отклонить запрос. Рядом находится
   проверка готовности: офлайн-вход, сохранение, билеты и свежесть копии.

Старые кнопки выгрузки **незашифрованного** JSON с расходами внутри маршрута
отключены. Вместо них открываются общие защищённые настройки. Это работает
и с уже загруженным личным маршрутом, без повторного импорта.

**Важно:** новый личный JSON и защищённая копия — разные форматы. Полную копию
загружайте через «Восстановить защищённую копию», а обновление маршрута — через
«Обновить маршрут из JSON». Защищённую копию никогда не отправляйте в публичный
репозиторий.

## Защита данных

- В GitHub можно хранить только файлы из этого публичного пакета. Никогда не
  загружайте личный JSON, резервные копии маршрута или старый исходный код.
- Скрипт публикации отклонит JSON-файлы в папке `public`, а на GitHub Pages
  отправит только содержимое `public/`.
- Импортированный маршрут шифруется браузером и хранится **на конкретном
  устройстве и для конкретного адреса сайта**, не на GitHub.
- На другом телефоне/ПК понадобится вручную восстановить защищённую копию
  или импортировать личный JSON повторно. Автоматической синхронизации нет.
- Храните личный JSON и защищённую резервную копию отдельно. После очистки
  данных браузера восстановление отметок и билетов возможно только из
  защищённой копии **при наличии её пароля**. При потере пароля можно заново
  импортировать исходный личный JSON, но не восстановить прежние отметки.
- Изменение адреса сайта (включая перенос с ChatGPT Sites на GitHub Pages)
  создаёт новое отдельное браузерное хранилище; импорт потребуется заново.

## Структура

- `public/` — только публичные файлы сайта.
- `.github/workflows/pages.yml` — автоматическая проверка и публикация.
- `.gitignore` — защита от случайного добавления частного JSON.

GitHub Pages на тарифе GitHub Free требует **публичный** репозиторий.
Поэтому публичной должна быть только оболочка сайта, а не личная информация.
